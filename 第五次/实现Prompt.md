# 数据看板实现 Prompt

> 以下为本次课后作业所使用的完整实现 Prompt，可直接交给代码模型复现项目。

---

## 角色

你是一名注重细节的前端工程师，同时具备信息设计和无障碍意识。请独立完成一个可直接运行的响应式经营数据看板，不要使用任何前端框架或第三方 UI 库。

## 任务

使用 **HTML + CSS + 原生 JavaScript**，实现一个名为「澄光数据」的经营数据看板。页面需要在手机、平板、桌面三档宽度下都有完整的布局和交互，不能只是把桌面版缩小。

## 硬性约束

1. **纯原生技术栈**：只使用 HTML、CSS、原生 JavaScript。不得使用 React / Vue / Tailwind / Bootstrap / jQuery，不得依赖构建工具。
2. **可直接打开**：`index.html` 在 `file://` 协议下双击即可运行，因此脚本使用普通 `<script defer>`，不要使用 ES Module 或 fetch 本地 JSON。
3. **三档断点**：
   - `< 768px`：卡片单列；
   - `768px – 1199px`：卡片两列；
   - `≥ 1200px`：卡片四列，并出现常驻左侧栏。
4. **卡片布局**：使用 CSS Grid 的 `auto-fit` / `minmax()`，或 `flex-wrap`。不得给内容区写死 `width: 1200px`。
5. **无横向滚动**：页面在 `320px–1920px` 全区间内不能出现横向滚动条。所有网格子项要允许收缩，文本和图表不能撑破容器。
6. **数据卡片由 JS 渲染**：页面恰好有 6 张数据卡片，必须由 JavaScript 数据数组生成。HTML 中只能有一个空容器，不得提前写 6 段重复的卡片 HTML。
7. **随机排序**：每次刷新页面，6 张卡片的顺序随机；提供一个「打乱卡片」按钮，点击后重新排序。使用 Fisher–Yates，并保证连续点击时顺序一定变化。
8. **数字不抖动**：所有数字使用 `font-variant-numeric: tabular-nums`，切换主题或更新数值时字宽稳定。
9. **颜色变量 + 主题切换**：所有颜色由 CSS 自定义属性管理；至少实现浅色 / 深色两套主题，并在页面右上角提供切换按钮，使用 `localStorage` 记忆，刷新后保持。
10. **图标规范**：不使用外部图片。所有图标使用内联 SVG，显式写 `width` 和 `height`，颜色使用 `currentColor`。
11. **语义化**：
    - 页面有且只有一个 `h1`，区块标题用 `h2`，卡片标题用 `h3`；
    - 每张数据卡片使用 `<section>`；
    - 所有可点击的切换控件使用 `<button type="button">`；
    - 导航使用 `<nav>`，图表有可读的等价文本；
    - 键盘可完整操作，有清晰的 focus-visible 样式。
12. **响应式细节**：在 320px 下不能出现文字截断、按钮溢出、图表被裁切；在 1920px 下内容不能无限拉伸到难以阅读。

## 页面内容

### 1. 左侧栏

- 品牌标识：几何四角星内联 SVG +「澄光数据 / LUMEN ANALYTICS」。
- 工作区信息：「零售事业部」+ `PRO` 小标签。
- 导航：经营总览、核心指标、趋势洞察、渠道贡献；每项带内联 SVG 图标，当前项高亮。
- 侧栏底部：本月营收目标卡片（¥128,640 / ¥150,000，完成 86%，进度条），数据连接状态，用户信息。
- `≥1200px` 时常驻；小于 1200px 时改为抽屉，点击顶部菜单按钮打开，支持遮罩、关闭按钮、Esc 关闭。打开时背景内容 `inert`，关闭后焦点回到菜单按钮。

### 2. 顶部栏与页头

- 顶部栏：移动端菜单按钮、面包屑、日期范围胶囊、主题切换按钮。
- 页头左侧：实时状态标签、`h1`「经营数据总览」、两行副标题、日期 / 门店数信息胶囊。
- 页头右侧：经营健康度 92/100 环形指示卡片，显示「状态良好 / 优于 87% 同类门店」。
- 宽屏时页头左右分栏，窄屏时上下排列。

### 3. 核心指标

- 区块标题 `h2`「六个关键信号」，右侧提供「打乱卡片」按钮和“每次进入随机排序”的提示。
- 6 张卡片的数据如下（可自行润色文案，但数值结构保持一致）：

- 每张卡片使用不同的强调色（紫、青、琥珀、玫红、蓝、绿），颜色通过卡片上的局部 CSS 变量控制。
- 折线图用内联 SVG，根据数组生成平滑曲线，带渐变面积和端点圆点；不得使用图片。
- 桌面端最后两张卡片各跨两列，使第二行刚好填满四列，避免留下两个空洞。

### 4. 趋势与渠道

- 左侧面板：近 7 日营收走势，累计 ¥78.4 万，较上周 +14.2%；用 7 根 CSS 柱状图展示，周六为峰值，柱顶显示数值。
- 右侧面板：渠道贡献，按订单量占比展示门店自提 42%、微信小程序 31%、外卖平台 18%、其他渠道 9%；每项包含进度条、金额和订单数。
- 面板在宽屏两列，窄屏单列。图表要有 `role="img"` / `aria-label` 或隐藏的等价文本。

### 5. 页脚

- 版权信息、技术栈说明，风格克制。

## 视觉方向

- 风格：现代、干净、有呼吸感的 SaaS 数据看板；不要花哨的霓虹赛博风。
- 浅色主题：暖灰蓝背景 `#f4f6fb`，白色卡片，深墨蓝文字，靛蓝作为主强调色。
- 深色主题：近黑蓝背景 `#070c17`，深蓝灰卡片，浅色文字，强调色适当提亮。
- 侧栏在两种主题中都保持深色，形成稳定的视觉锚点。
- 卡片：20px 左右圆角，细边框，轻阴影，右上角有非常淡的彩色光晕；标签、数值、图表形成清晰层级。
- 字体：系统字体栈；中文优先「Microsoft YaHei UI / PingFang SC / Noto Sans SC」。
- 动效：卡片入场错峰淡入、柱状图向上生长、状态点呼吸；不超过 700ms。遵循 `prefers-reduced-motion: reduce`，在减少动态时关闭。
- 禁止使用外部图片、外部字体、在线图标库。

## 交互与可访问性

- 主题按钮需同步 `aria-pressed` 与 `aria-label`（例如“切换到深色模式”），主题写入 `localStorage`，首次访问读取系统偏好。
- 「打乱卡片」按钮需要在重排后通过 `aria-live` 区域播报结果。
- 抽屉打开时锁定 body 滚动，Esc 可关闭，Tab 焦点保持在抽屉内；关闭后焦点还原。
- 为导航添加滚动高亮；当前项使用 `aria-current="location"`。
- 进度条使用 `role="progressbar"` 并提供 `aria-valuenow` / `aria-valuetext`。
- 装饰性 SVG 加 `aria-hidden="true"`；有意义的图形补充文字说明。
- 对比度：正文和辅助文字尽量满足 WCAG AA；小字号文本不要使用过浅的灰色。

## 验收清单

完成后必须逐项自测并给出结果：

- [ ] 320、360、390、768、1024、1199、1200、1440、1920px 均无横向滚动。
- [ ] 767px 单列，768px 两列，1200px 四列且侧栏可见。
- [ ] DOM 中恰好 6 张卡片，每张都是 `section`，没有 6 段重复 HTML。
- [ ] 刷新和点击按钮都能打乱顺序，顺序确实发生变化。
- [ ] 5 次连续打乱后仍是 6 个唯一指标。
- [ ] 数字的计算样式包含 `tabular-nums`。
- [ ] 浅 / 深主题可切换、刷新后保持，切换前后页面宽度不变。
- [ ] 所有图标 SVG 有明确的 `width`、`height`，并使用 `currentColor`。
- [ ] 1 个 `h1`、至少 2 个 `h2`；所有按钮有 `type="button"`。
- [ ] 移动端抽屉可用键盘关闭，焦点管理正确。
- [ ] 浏览器控制台无报错。
- [ ] 320px 下没有卡片文字或按钮被裁切。
